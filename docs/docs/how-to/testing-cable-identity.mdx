# Determine a cable's characteristics

The Cable Test function reads the identity advertised by an electronically marked
USB-C cable. It supports Dr. PD hardware revision R2605-A and either plug orientation.

1. Select **Mode → Cable Test...** from the menu.
2. Connect either end of the cable to **Port 1 (DUT)**, leaving the other end unplugged.
   Discovery starts automatically.
3. Dr. PD fills the identity and capability fields with the information retrieved
   from the cable's e-marker, if it responds with a valid identity.
4. Close the dialog to return Dr. PD to **Disabled** mode.

The firmware detects the cable's Ra termination, powers the corresponding VCONN
contact, and sends a structured `Vendor_Defined` Discover Identity request to SOP′
on the other CC contact.

The dialog groups the results into **General Information**, **Cable Information**,
and, for active cables that report these details, **Active Cable Features**.
These sections show the cable type, connector type, vendor ID, advertised current
and voltage limits, USB speed class, and other reported capabilities. The speed
indication describes the maximum signalling rate associated with the reported
class; actual transfer speed depends on the connected devices and operating mode.

:::note
The returned information represents the manufacturer's claims stored in the
cable's e-marker. Dr. PD checks the response format, but it does not measure the
cable's performance or verify that it meets those claims.
:::

## Interpret the results

- **“No cable detected, damaged cable, or cable without an e-marker.”** means
  that Dr. PD has not received an identity or a matching `GoodCRC` acknowledgement.
  An empty port, an unmarked cable, or a cable whose e-marker cannot respond can
  produce this message. Ensure that the far end is unplugged and connect the
  cable to Port 1.
- **“E-marked cable detected.”** means that Dr. PD received an identity or a
  matching `GoodCRC` acknowledgement from the cable. The capability fields remain
  blank unless a valid identity response is received.

More detailed outcomes are available through the
[CABLE commands](../programming-guide/controlling-dr-pd-over-scpi/reference/cable):
`NO_RESPONSE` means no matching acknowledgement was received after bounded retries;
`RESPONSE_TIMEOUT` means the request was acknowledged but no identity response
arrived; `NAK` means the responder declined the request; `MALFORMED` means the
identity response was invalid; and `POWER_FAULT` means VCONN did not reach the
required voltage. A power fault does not imply that the cable sent an invalid message.

:::note
Dr. PD's VCONN circuit is designed for low-current e-markers requiring about 5 mA
or less, so compatibility with every active cable is not guaranteed. Testing both
ends and orientations can expose asymmetric faults, but it does not test the
continuity of every conductor.
:::
